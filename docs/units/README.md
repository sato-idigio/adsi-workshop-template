# Unit of Work 分割 — 勤怠管理システム

## 分割方針

- **2人で並行実装**できるように、依存の少ない Unit に分割する
- 共通基盤（プロジェクト骨格・認証・マスタ管理）を最初に完成させ、以降の Unit が独立して実装可能にする
- 各 Unit は Backend + Frontend をセットで含む

## Unit 一覧

| Unit | 名前 | 担当 | 依存 |
|------|------|------|------|
| Unit 0 | 共通基盤（プロジェクト骨格・認証・社員/部署管理） | 共同 | なし |
| Unit 1 | 打刻・勤怠一覧 | 担当A | Unit 0 |
| Unit 2 | 休暇管理 | 担当B | Unit 0 |
| Unit 3 | 打刻修正（申請・承認） | 担当A | Unit 0, Unit 1 |
| Unit 4 | 月次レポート | 担当B | Unit 0, Unit 1 |

## Phase 計画（2人並行）

| Phase | 担当A | 担当B | 備考 |
|-------|-------|-------|------|
| Phase 0 | Unit 0（共同作業） | Unit 0（共同作業） | テスト実行環境込み。ここが完成してから分岐 |
| Phase 1 | **Unit 1** 打刻・勤怠一覧 | **Unit 2** 休暇管理 | 並行実装 |
| Phase 2 | **Unit 3** 打刻修正 | **Unit 4** 月次レポート | 並行実装（Unit 1 完了後） |

## 各 Unit の概要

### Unit 0: 共通基盤

テストが実行できるプロジェクト骨格 + 認証 + マスタ管理。全 Unit の土台。

- Gradle / Next.js プロジェクトの初期化
- PostgreSQL + Flyway セットアップ
- Spring Security + JWT 認証
- グローバル例外ハンドラー
- 社員 CRUD / 部署 CRUD
- Frontend: ログイン画面・レイアウト・API クライアント基盤
- **テストインフラ**: JUnit 5 + テスト用 DB(H2 or Testcontainers) + Vitest

### Unit 1: 打刻・勤怠一覧

出勤/退勤の打刻と月次勤怠一覧。ドメインの中核。

- 出勤打刻 / 退勤打刻 API
- 勤務時間・残業・深夜時間の自動計算
- 当日の打刻状況取得
- 月次勤怠一覧 API
- Frontend: ダッシュボード（打刻ボタン）・勤怠一覧画面

### Unit 2: 休暇管理

有給・半休・特別休暇・代休の申請と承認。打刻ドメインに依存しない。

- 休暇申請 API（種別に応じた日数計算）
- 承認 / 却下 API
- 有給残日数管理
- Frontend: 休暇申請画面・休暇承認画面（管理者）

### Unit 3: 打刻修正

打刻レコードへの修正申請と承認。Unit 1（AttendanceRecord）に依存。

- 打刻修正申請 API
- 承認時に AttendanceRecord を更新
- Frontend: 打刻修正申請画面・打刻修正承認画面（管理者）

### Unit 4: 月次レポート

月次集計の生成と管理者向け閲覧。Unit 1（AttendanceRecord）のデータを集計。

- 月次集計バッチ処理（Service）
- 管理者向け集計レポート API
- Frontend: 月次レポート画面（管理者）
